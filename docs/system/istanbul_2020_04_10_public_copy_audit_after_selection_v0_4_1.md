## 4.2 Main copy problems

### 1. Grammar / syntax issues are still visible

Clear examples:

- `Venüs üçgen Satürn kadar Güven de bu hattın karakterini belirliyor.`
- `Merkür'ünün 11. evde Balık'ta olması kadar Yükseleninin İkizler olması de bu hattın karakterini belirliyor.`
- `Yükseleninin İkizler Venüs 1. ev olması...`
- `Yakınlık burada hafif ilerlemez; Bir anda derine çekilir.`
- `Duygun, günlük akışta bile kolay yüzeyde kalmayabilir; Küçük şeyler içeride daha derine işleyebilir.`
- `Güneş'inin 12. evde Koç'ta olması ile Özel ateş birlikte...`

These are not small stylistic preferences. They read as composition bugs.

### 2. One core block still has a broken ending

`core_blocks[1]` career body ends with:

- `Bazen de.`

That block is not release-ready in current form.

### 3. Template spine is still too visible

Repeated skeletons remain common:

- `X kadar Y de bu hattın karakterini belirliyor`
- `X ve Y aynı çizgiyi güçlendiriyor`
- `bu hattın imzasını netleştiriyor`
- `bu çizginin sağlam yanını oluşturuyor`

This is improved from the earlier renderer state, but it still sounds generated rather than authored.

### 4. Some blocks repeat themselves inside the same paragraph

Examples:

- `core_blocks[2]` uses the same sentence twice:
  - headline `Ne yapacağını bildiğin an tempo kendiliğinden yükselir.`
  - body repeats `Ne yapacağını bildiğin an tempo kendiliğinden yükselir.`

- `extra_blocks[4]` repeats the same semantic twice:
  - headline already says `içine oturan bir güven`
  - body again says `Sen ilişkide yüzeysel bir sıcaklıktan çok, içine oturan bir güven arıyorsun.`

### 5. V8 differentiators are still too close to already-used surfaces

The first differentiator is effectively a duplicate of the career core card:

- core headline: `Görünür işte cesur başlatıcılık, bağımsız hareket ve canlı yön duygusu.`
- differentiator[0] headline: same sentence

That weakens the sense that differentiators are additive.

### 6. Family labels feel off in a few places

- `gemini_asc_venus_1h_social_relational_presence` uses `family = mind_mechanics` even though it is functioning as identity/social-presence copy.
- `sun_aries_12h_hidden_private_fire` also carries `family = mind_mechanics`.

This is not a public bug by itself, but it suggests the voice/family routing still has some conceptual bleed.
